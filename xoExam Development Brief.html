Executive summary

Between April 27 and June 2, 2026, the xoExam™ UI/UX prototype progressed through fourteen versioned releases (v0.1.0 through v0.2.6). The work covered three connected efforts: (1) establishing the application shell — login, welcome, dashboard, navigation, supporting admin pages; (2) rebuilding the doctor and module ecosystem as the unified hub for xoExam™, xoIris™, xoFit™ and xoLab™; (3) bringing the 19 ophthalmic tests onto a single shared test framework with clinically accurate scoring, one or more tests per release.

The reusable patterns established across the rollout — the OD/OS/OU eye sequence, in-test eye picker, three-phase shared test framework, canonical cancel experience, and Doctor sign-off — generalize to every remaining test in the suite, which is why each new test reaches clinical fidelity faster than the last.

  • Esterman Binocular Functional Test added; Eyes Converging Exam added; duplicate Wavefront entry removed

Stability and polish pass

Interim deploy covering routine refinements, minor UI corrections, and stability improvements ahead of the larger structural work in v0.1.2.

v0.1.2 May 14, 2026 Doctor ecosystem

Full Doctor section rebuild as the XO™ ecosystem hub

In response to the client Figma audit, the previously brief doctor view was rebuilt into a full-page tabbed profile experience. Each doctor record is now the central hub linking out to the entire XO™ Vision Care System.

  • Six-tab DoctorProfile: Overview · Contact · Credentials · Schedule · Connected Modules · Reviews
  • Connected Modules tab makes the doctor record the link point for xoExam™, xoIris™ (cloud-linked), xoFit™ (locked, sales-contact), xoLab™ (locked, sales-contact)

  • Stats bar, sort menu, per-doctor action menu added; doctor and messaging pages split into separate sections
  • Nomenclature swept across the application: xoExam™ / xoIris™ / xoFit™ / xoLab™ standardised everywhere
v0.1.3 May 14, 2026 Module ecosystem

Per-product module tabs and marketing surfaces

The single Connected Modules tab was split into one tab per product so each XO™ product has dedicated real estate. Cloud-connected modules show live data; future modules become marketing surfaces.

  • xoIris™ tab (connected): Connected status pill, last-sync timestamp, "Open xoIris" deep link, 4-up data stats grid (synced appointments, today's schedule, no-show flags, pending confirms)
  • xoFit™ and xoLab™ tabs (future products): full marketing layout — product-color headline, supporting copy, real product imagery, "Contact XO Sales" and "Learn More" CTAs

  • Self-service photo upload affordance added for the logged-in doctor
v0.1.4 May 15, 2026 Architecture standardisation

Shared test framework + canonical cancel experience + Visual Acuity to full clinical fidelity

First delivery under the test-stream architecture: Visual Acuity was completed to full clinical fidelity in a dedicated stream and integrated into the main prototype via the new shared test harness. Every subsequent test mounts into the same shell, which owns the timer, exam header, patient info, and the safety-critical cancel-test confirmation.

  • Visual Acuity test: complete clinical readout — individual line and full chart views, per-eye OD/OS/OU results, three-state letter responses, mark-all-correct/incorrect, regenerate letters, auto-progression at ≥65%, prescription adjustment panel (SPH/CYL/AXIS for OD and OS), detailed report with VA table, prescription summary, Export and Compare actions
  • Canonical cancel experience across all 19 tests: back arrow hidden during testing (no accidental data loss); a labelled red "Cancel test" button replaces it; clicking opens a confirm modal with a destructive "Cancel test" option and a default "Continue test"
  • Test-stream pattern documented as the contract for all future test integrations — each test ships an approval-ready demo plus a shell-ready component, byte-identical between the two
v0.1.5 May 15, 2026 Color Vision rebuild

Color Vision rebuilt: Ishihara + D-15 unified onto the shared framework

The Color Vision test was rebuilt in three atomic batches — structural cleanup, integration onto the shared framework, then user-experience polish. The result: a single Color Vision test that runs both Ishihara screening and D-15 Farnsworth from a unified entry point.

  • Ishihara text-input replaced with a touch-friendly 3×4 number pad (1–9, backspace, 0, submit) plus a "No response" button
  • Session notes textarea added to both Ishihara and D-15 right sidebars
  • Defect bands aligned to American Academy of Ophthalmology three-band convention: Normal color vision · Borderline · Deficiency detected
  • Visual Acuity-style report structure: header card, score hero, clinical interpretation, patient information, plate-by-plate results, D-15 results
v0.1.6 May 15, 2026 Color Vision polish

D-15 cap UI polish — anti-cheat correction and homogenised workflow

Two client-flagged corrections to the D-15 test. The Finish & Report flow was unified between the two protocols, and a workflow defect that let patients "cheat" the cap arrangement by sorting numbers was closed.

  • Finish & Report button wired in the shared header during D-15 — replaces the previously redundant inline "Complete Test" button
  • Cap numbers removed from the patient-facing arrangement UI (caps were trivially solvable by sorting numeric labels instead of matching colors); cap identifiers remain available internally for scoring and the post-analysis sequence display
  • Reference cap copy clarified for clinical accuracy; cap visual size increased for touch targets
v0.1.7 May 15, 2026 Clinical accuracy

Color Vision clinical accuracy overhaul — second test to full clinical fidelity

Color Vision became the second test in the system to reach full clinical fidelity (after Visual Acuity in v0.1.4): the standard mono-mono-binocular eye sequence, industry-standard scoring methodology, and clinically realistic stimulus presentation. The eye-sequence pattern established here generalises to every remaining mono-mono-binocular test in the suite.

  • OD → OS → OU clinical sequence: each Color Vision protocol now runs as three discrete tests — right eye monocular, left eye monocular, both eyes binocular — with patient-positioning prompts between phases. Doctor can choose any start eye; default is OD.
  • In-test eye picker with a 3-pill OD/OS/OU selector at the top of each test, locking once the patient begins to prevent accidental data loss
  • Vingrys & King-Smith (1988) scoring implemented — the same moment-of-inertia method used by every commercial D-15 software since publication. Generates the six clinical indices: Confusion Angle, Major Radius, Minor Radius, Total Error Score, S-index, C-index
  • Cap palette upgraded from the previous vivid rainbow to clinically realistic Munsell-derived hues at near-constant luminance — sorting now requires genuine hue discrimination as it does on the physical D-15 plates
  • Cumulative report shows up to three eyes per protocol with patient classification (worst-monocular-eye, clinical bottom line), binocular function note, full V-K-S indices table, Vingrys & King-Smith reference population values, three-zone severity strip, and a clinical polar diagnostic plot with confusion-line overlays for at-a-glance defect-type reading
  • Ishihara plates 5–24 (no licensed image yet) now display session-stable simulated numbers blended into the dot field so the design-testing flow can score correctly; small "simulated" tag marks them as non-clinical
  • D-15 launch icon cropped to just the colorful circular logo
v0.1.8 May 18, 2026 Visual Fields

Visual Fields to clinical fidelity + first formal engineering handoff

The Visual Fields perimetry test was rebuilt to clinical fidelity, and the first formal Engineering Handoff Specification was issued to document the integration contract for the development team.

  • Clinical perimetry readout: Glaucoma Hemifield Test category, Total Deviation and Pattern Deviation probability plots, age-banded reference values, reliability indices (fixation losses, false positives, false negatives)
  • OD → OS bilateral sequence for monocular patterns; single binocular run for by-design binocular protocols (Esterman and equivalents)
  • Multi-phase pre-test flow (eye selection, configuration, pattern, foveal calibration) collapsed cleanly under the shared three-phase framework
  • Engineering Handoff Specification v0.1.8 issued — quick start, component contract, integration touchpoints, open-decisions agenda, regulatory acknowledgment
v0.1.9 May 21, 2026 Wavefront Aberrometry

Wavefront Aberrometry to clinical fidelity + Doctor sign-off pattern

Wavefront Aberrometry was extracted to its own component and rebuilt to clinical fidelity at a corrected 6.0 mm analysis diameter so its higher-order-aberration values match published norms. This release introduced the Doctor sign-off pattern now used across all clinical-fidelity tests.

  • Clinical interpretation driven by higher-order RMS thresholds; Total HOA and Coma RMS surfaced as primary metrics; per-eye patient classification banner
  • Wavefront map with view-type selector, color-scale legend, and proper Zernike notation; axis corrected to unsigned 0–180°
  • "Doctor sign-off" label introduced above Certify & close — groundwork for the eventual roles & remote-operation model
v0.2.0 May 21, 2026 Naming & housekeeping

Naming convention sweep + catalog cleanup

A repository-wide housekeeping release with no new clinical content. The client-approved test-naming convention was applied throughout: UI labels use bare nouns (no redundant "Test"/"Exam" suffix), while formal reports keep their full clinical phrasing.

  • Catalog, launchers, and exam-header titles swept to the bare-noun convention
  • Dead and duplicate catalog entries removed; routing fallbacks audited so no unknown route can blank the screen
v0.2.1 May 22, 2026 Extraocular Motility

Extraocular Motility to clinical fidelity

Extraocular Motility was extracted to its own component and rebuilt to clinical fidelity, with the grading scale corrected to the international standard and the position set completed to nine cardinal positions.

  • Grading scale corrected from an arbitrary 1–5 to the international standard 0 to ±4 (0 = normal, underaction negative, overaction positive)
  • Nine cardinal positions including primary gaze; each position carries primary and secondary muscle / cranial-nerve mapping so a CN IV palsy is read correctly
  • H-pattern motility diagram (clinical standard); cranial-nerve palsy flag surfaced prominently; sub-test state machine (versions → pursuit → saccades → ductions)
v0.2.5 May 22, 2026 Pupillometry

Pupillometry to clinical fidelity

Pupillometry was rebuilt from a static-only sketch into a full clinical-fidelity component with three sub-tests, age-banded reference ranges, and a four-pattern clinical flag system.

  • Three sub-tests: static pupil sizing (three light conditions), dynamic pupillary light reflex (live curve + six metrics + NPi composite), swinging flashlight with per-eye RAPD grading
  • Age-banded reference range (Winn 1994) driven by patient age; light-vs-dark anisocoria differential rule
  • Four-pattern clinical flags: sympathetic (Horner's), parasympathetic (CN III), optic-nerve RAPD, neurological NPi
v0.2.6 · Current June 2, 2026 Wavefront Refraction

Wavefront Refraction — the combined autorefractor + phoropter replacement

v0.2.6 adds Wavefront Refraction, the most clinically consequential test in the suite. It is the combined digital replacement for the traditional two-instrument refraction workflow, and its verified prescription is the gate that releases the job to the downstream xoFit fitting workflow. It is added as a new, parallel test that supersedes — but does not remove — Wavefront Aberrometry; both stay in the catalog.

  • Stage 1 — Objective: monocular wavefront capture (OD → OS) using the live eye-scan presentation — dark viewer, breathing pupil, sweep line, and a red alignment dot that turns the backdrop green on lock — with a documented scan count (1–3) per eye
  • Stage 2 — Subjective: liquid-lens digital phoropter refinement, step sequence sphere (MPMVA) → JCC axis → JCC power → add, per eye
  • Clinical non-negotiables baked in: axis-before-power JCC ordering, +0.75 D fogging prompt, sphere-compensation note, signed two-decimal prescription discipline, monocular capture (no averaging across eyes)
  • Certify & close is a system event — it releases the verified prescription downstream; flagged to engineering as the integration trigger, not a UI-only action
  • Deliberately no clinical claims in the report — a refraction is a measurement-and-verification workflow, not a screening, so no interpretive banner is shown
  • Standalone Visual Acuity gained geometric Tumbling E and Tumbling C optotypes, shared with the subjective phoropter stage
